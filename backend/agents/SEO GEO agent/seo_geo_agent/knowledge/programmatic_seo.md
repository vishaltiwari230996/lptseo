# Pages-at-scale judgement (distilled from the programmatic-seo playbook)

When the brand asks about location pages, centre pages, template pages, or
"should we build a page for every X" — this is the rulebook.

## Core principles
- UNIQUE VALUE PER PAGE: every page must carry value specific to itself, not
  a template with swapped city names. Swapped-variable pages are exactly what
  thin-content and doorway-page penalties target.
- QUALITY OVER QUANTITY: 100 genuinely useful pages beat 10,000 thin ones.
  Never recommend generating pages for patterns with no search demand.
- DATA DEFENSIBILITY (strongest first): proprietary data you created →
  product-derived → user-generated → licensed → public. A programmatic play
  on public data anyone can copy has no moat.
- URL STRUCTURE: subfolders, not subdomains (`site.com/jaipur/` not
  `jaipur.site.com`) — subfolders consolidate authority, subdomains split it.
- INTENT MATCH: the page must actually answer what the searcher wants, not
  merely contain the keyword.

## For a coaching/service business, per-location pages need
Faculty, batch timings, results from THAT centre, address with map, fees,
local reviews/testimonials — the things a visitor to that centre asks. If the
only difference between two centre pages is the city name, consolidate or
differentiate before building more.

## Architecture
- Hub and spoke: category hub page → individual pages, cross-linked between
  related spokes. Every page reachable from the main site; no orphans.
- Breadcrumbs with structured data; separate sitemaps by page type.
- Noindex the very thin variations instead of deleting them, while they are
  being built out; prioritise the high-volume patterns first.

## Watch for after launch
Indexation rate (are the pages even being indexed?), thin-content warnings,
cannibalization between generated pages, rankings vs the effort. Pages that
exist for Google rather than users show up as high bounce + zero conversions
— recommend pruning or merging those, not making more.
